# Swift SDK validation

This records local qualification of the portable Swift migration. See [the final acceptance review](ACCEPTANCE.md) for requirement mappings and explicit limits. The sections below retain historical failures and their subsequent evidence; they do not all describe the current state.

The user requested local-only validation on 2026-10-22. CI is no longer an acceptance gate for this task, and no further CI runs should be triggered. Historical CI results below identify observed failures; they do not replace local investigation or add a remote completion requirement. Full functional coverage remains required.

## Subscription sign-in

The complete upstream `test-chatgpt-sign-in.mjs` and `test-grok-sign-in.mjs` files pass through Swift with their original assertions. The loader changes only their imports. A separate test adapter forwards operations and HTTP fixture callbacks to `FxSignIn`; Swift owns PKCE, callback validation, token exchange, device-code lifetime and polling, slowdown, account lookup and credential refresh. The independent Release consumer imports these public APIs without test access, saves and restores both authorization types, finishes both flows against an injected HTTP fixture, normalizes credentials and refreshes them.

The implementation uses Foundation and CryptoKit without another dependency. The design follows the external-browser and PKCE boundary in [RFC 8252](https://www.rfc-editor.org/rfc/rfc8252) and polling/slowdown behavior in [RFC 8628](https://www.rfc-editor.org/rfc/rfc8628). Provider-specific endpoints and grants follow the current libfx sources. The host owns browser presentation and credential storage.

## Minimal API and HTTP cleanup

The complete upstream minimal API, configuration-isolation, native cancellation, host-fetch failure, native streaming and late host-tool settlement files pass through Swift with their assertions unchanged. The bridge keeps its two fixture-only controls nonenumerable. Swift owns streaming, reasoning, usage, model and authorization forwarding, checkpoints, repeated close and cancellation. Configuration isolation verifies that the kernel uses explicit instructions without scanning workspace context, launching workspace MCP or making a native billing request.

The native transport distinguishes active, successfully consumed and retired fetch handles using the shared core's coherent disposition. After successful model consumption, it discards response-tail bytes until EOF, with a 100 ms wait and a 64 KiB tail budget. EOF releases the response without cancellation. A cancelled or retired request still cancels promptly. The next model step and engine close await bounded cleanup of consumed responses. No legacy Node-addon fallback is implemented in the Swift SDK.

Two parameterized native tests cover four cases: delayed EOF, tool-step ordering, an indefinitely stalled tail and a tail larger than the byte budget. The byte-budget case offers EOF after 30 ms, so relying only on the 100 ms timer fails the test. A separate JavaScript/Swift comparison uses actual loopback HTTP and verifies connection reuse across fresh engines, successful completion without abort, stalled-tail cancellation, byte-budget cancellation before offered EOF and tool-step ordering. All 239 native tests pass locally in normal, Address Sanitizer and Thread Sanitizer builds.

The upstream native streaming stress owner exposed an output-queue overflow under Address Sanitizer. A diagnostic run identified the native transport's second, 256-chunk Swift queue. The transport now uses the standard library's pull-based [`AsyncThrowingStream(unfolding:)`](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0314-async-stream.md): it drains at most one native chunk when the RPC reader asks for it, while readiness still services model fetches. The shared core retains its 8 MiB output bound. This removes the duplicate queue instead of increasing its capacity. The original streaming owner passes after the change under Address Sanitizer and Thread Sanitizer. Both sanitizer builds also pass the real-HTTP comparison, native request cancellation and late host-tool settlement owners. Added native tests hold the output reader idle across 385 RPC responses, then check every response in order, and check close releasing an idle read.

The complete upstream HTTP cleanup owner remains unqualified: it also injects N-API function wrappers and tests an older addon without coherent disposition. The Swift adapter does not use those injected Node handles. The raw pre-fetch-cancellation owner likewise mixes direct N-API operations with an injected late-publication race. Neither owner is reported as passing through Swift. The empty-image rich-tool frame fixture also remains unqualified: Swift encodes a text-only typed result directly, so its JavaScript fixture does not cross the same frame limit. Existing native tests qualify frame-size fallback with actual rich images; continuation at that boundary remains a separate coverage item.
